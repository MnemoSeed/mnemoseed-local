# PRD 251 / 236 / 231 合并收尾记录

范围：把三条既有队列工作作为**一个**收尾批次落地。变更面限于测试、门禁脚本与 CI；产品面不变——不改凭据策略、路由、默认值、模型、全局配置或已安装运行时。

## 理论锚

**本批次无借用理论。** 三条工作全部属于工程正确性与测试可靠性：调用者凭据边界、重载隔离的可检测性、每条提交的廉价门禁。设计规则来自仓库既有约定与失败模式。

**未借用（显式排除）**：不引用任何神经科学、认知科学或心理学结论作为设计依据；不以记忆/学习机制、脑区、可塑性、间隔效应类说法支撑任何判定。若后续材料出现此类表述，视为越界。

## 三条工作的边界

### #251 调用者凭据守卫

- 凭据只允许出现在受支持的请求头位置；出现在请求体或错误的位置参数槽位时必须拒绝。
- 受支持文本语法（js / ts / cmd / bat）中的**注释**不得构成有效认证；生产方辅助函数写入的头部值仍须被接受，守卫不得误杀正向路径。
- 扫描覆盖根级 js/ts/cmd/bat 调用者及其后缀变体。
- 逐语句目标分类：每条拨号语句必须解析到可读的调用目标；目标隐藏且无法解析时一律判失败。
- 明确的外部 URL 下载器与声明式参数转发保持开放，不判失败；不设注册表豁免，不得以登记白名单绕过判定。
- 路由诊断噪音受控：不泄漏凭据、不改变路由结果。
- 回归覆盖四类：头部、请求体、注释、根级后缀。

### #236 重载隔离

- 定义异常类的模块被 `importlib.reload` 不安全重执行时须被检出。
- 本命名空间 `exec` 源码扫描同样纳入判定，不依赖 reload 单一路径。
- 安全模块与子解释器隔离路径须保持正向有效。

### #231 每条提交的廉价门禁

- `scripts/check_commit_range.py` 对范围内**每一条**新增提交执行廉价门禁：改动注释策略检查、`ruff check`、`ruff format --check`。
- 无父（root）提交**不自动失败**：以空树为基准比对，干净则通过。
- 空范围、不可读的范围或树、缺失检查器，一律失败闭合，不得静默通过。
- 合并提交与其**第一个父提交**对账；失败必须可见，不能藏进合并提交被吞掉。
- 类型检查与测试套件仍在 tip 上各读一次；该脚本不是放行未通过测试或类型的许可证。

## 验收口径

**正向（须保持绿）**：生产方辅助函数头部值被接受；安全模块重载与子解释器隔离有效；范围内每条干净提交通过廉价门禁；干净 root 提交通过；正常范围的合并对账通过。

**反向（须为红）**：请求体携带凭据；错误位置参数槽位；注释伪装认证；隐藏且不可解析的拨号目标；异常类模块的不安全 `importlib.reload`；命名空间 `exec` 命中；范围内任一提交注释/ruff/format 不洁；空范围、不可读树、缺失检查器。

**依赖**：三条工作共享测试夹具面（`tests/conftest.py`、`tests/reload_guard.py`），写入串行推进；门禁脚本先落地，才可对一提交范围自证。
