# 11 · 记忆精炼层 v2（清醒整理设计）

状态：设计提案（v1 实证评估后重设计，评估见 org/workspace/dream-engine-evaluation-20261028/）。
取代：`02-dream-engine.md` 中的提取路径（池子积分触发 + 全量分批三元组提取 + 双席投票）。捕获层、向量召回层、注入层**不变**——它们是经实证在工作的部分。

## v1 失效事实（设计输入，全部实测）

1. 30 次 dream 运行：仅 8/17 的 1–4 chunk 小运行产出 2–8 条三元组（自指琐事），其余全部 0 产出；最后一次消化 15/11,428 chunk、溢出 11,413、空判定、111MB 快照。
2. `reflect_batch_max_tokens=8000` 对真实单 chunk（可达 34k token）不可分批 → 溢出永久积压。
3. 快照无大小守卫，把全部原始 chunk 内嵌进结果文件。
4. 双席投票从未配置（vote 角色无路由，恒回退单模型）；9 月预注册观测：20 对真实记忆投票仅 2 对被接受、席间一致率 90%——一致性高但接受率极低，产出价值密度不足。
5. 池子入账水位冻结（score_pool credit 路径死路），auto_trigger 永不满足。
6. graph 三个月仅 37 节点 / 0 边 / 0 次调和。

## 理论锚

只借用有实证基础的规律，与实现机制严格分离：

| # | Citation | 已验证规律 | 设计规则 |
|---|---|---|---|
| R1/R2（沿用 REFERENCES.md 已登记） | McClelland et al. 1995；Wilson & McNaughton 1994 | 系统巩固：离线、在编码之后、以有界重复进行，把近期情节整合进长期结构 | 整理是**会话结束后的离线批处理**，不在捕获热路径上；每个会话一个整理窗口，绝不面对无限流 |
| R56（新增登记，⚠️ 本轮未直接核验，经典高置信） | von Restorff (1933); Hunt & Worthen (2006) *Distinctiveness and Memory* | 独特性效应：与背景差异显著的项被记得更牢 | 精炼优先保留**差异事件**（错误→修复对、决策与反转、新工具/新约束首次出现），对均匀平淡内容只做一句摘要，不做逐条提取 |
| R4（沿用） | Tulving & Thomson 1973 | 编码特异性：提取线索决定可提取性 | 每条沉淀事实必须携带其来源会话 id 与原文锚点，供未来按线索检索与溯源 |

**显式不借用**：弗洛伊德式梦的象征解释（无实证）、左右脑分工神话、学习风格匹配（已被证伪）、莫扎特效应、记忆无限容量假设。

## 设计

### 触发：会话结束驱动，废弃池子积分

- 触发信号 = 宿主 **SessionEnd** 事件（不是 Stop：Stop 是每回合结束，按它触发等于回到热路径）。现状核对：Claude Code（7 事件含 SessionEnd）、Codex CLI（含 SessionEnd）、OpenCode（session.deleted → `POST /session/end`，守护进程端点已存在）三宿主信号就绪；ZCode 官方七事件里有 SessionEnd 但 v1 适配器只注册了四个——S2 切片补注册。宿主缺信号的过渡期用会话空闲收敛（复用 trigger 模块 idle 语义）作兜底。
- 一个会话 = 一个整理窗口；score_pool 自动触发路径**废弃**（其入账死路不再修复）；`dream --once` 保留为运维手动入口（对指定会话 id 或最近 N 个未整理会话执行）。
- 硬上限：同时排队窗口数 ≤ 8；最老积压超 7 天则告警（error_events），**永不**因积压自动放大批量。

### Phase 1：确定性提取（无 LLM，零成本）

从窗口内 chunk 的结构化字段直接抽取，逐条去重（对 chunk id + 字段哈希）：

- 执行过的命令与退出码；触碰的文件路径；错误行与其后 N turn 内的修复动作（成对存储）。
- 用户显式标记的决策（现有/未来的 decision 标记面）。
- 新首次出现的工具、约束、环境事实。

产出：结构化事实条目，每条携带 `{session_id, chunk_ids, kind, payload}`。

### Phase 2：单模型有界摘要（可选，可整体关闭）

- 覆盖职责在 Phase 1（确定性、无预算、看全部 chunk）；Phase 2 只做压缩，输入 = **Phase 1 事实清单 + 会话首尾摘录**（不是原始全文），按预算截断（默认 ≤ 8k token；超限按子窗口切分多次调用，每会话调用总数 ≤ 4）。长会话（数百回合）因此不丢覆盖——被丢的只是摘要粒度，且截断策略在此显式声明，无静默丢弃。模型 = 当前本地 dream 路由（qwen3.5:9b 或后续更优本地模型）。
- 输出严格 schema：`{summary: ≤200 字, facts: ≤5 条}`。**每条 fact 必须携带 verbatim 源文片段**。
- **接地校验（确定性，质量闸门的核心）**：归一化规则先声明——源文片段与目标文本都做**空白折叠**（连续空白/换行折成单空格）后做**逐 chunk 内**子串匹配（绝不跨 chunk 拼接匹配）；片段最短 N 字符（默认 16）才参与校验，杜绝碎片误命中。不匹配即丢弃该 fact 并计一次质量信号；**丢弃率 > 50% 的运行判为模型/提示词不合格**（记 error_events 并停用 Phase 2 直至调整），绝不静默全丢或全收。
- summary/facts 超预算 → 截断整条并丢弃，宁可少不可烂。

### 合并与沉淀

- 事实版本化走**键 supersede 专用路径**：以 `(subject, predicate)` 为键，同键新证 → 旧条降级为历史（supersede 链），不同键 → 新增。**这不是 design/12 的提名制调和管线**（那条管线解决双图指针互指冲突，依赖 nominate/adjudicate/merge 模块，运行记录为零）；本设计不假设复用它，事实 supersession 是独立的简化路径，接口边界在 S4 切片实现时钉死。
- 每条落图事实带 `source_session_id` 与 chunk 引用（**引用 chunk id，绝不再内嵌 chunk 正文**——chunk 本体只活在向量库）。
- 图边补全：事实 ↔ 会话 ↔ 实体（文件/命令/工具）建边，修复 v1 的 0 边问题。

### 守卫（全部 fail-loud）

- 快照文件硬上限 1MB（只存引用与产出，不存原文体）；超限 = 拒绝该窗口并记 error_events，绝不静默。
- LLM 调用超时/失败 → 窗口标记 retryable，重试 ≤ 2 次，仍失败则告警并跳过该窗口（下个会话不受影响）——**没有任何静默积压路径**。
- 产出验收阈值：新设计上线前，跑一轮抽样人工评审（≥20 个会话窗口，沉淀事实的"对未来对话有用"判定 ≥ 60% 才允许接入主图；不达标继续调，不硬上）。

### 明确不做

- 不做全量三元组提取（v1 实证无效）。
- 不做多席投票/双模型串行（从未配置 + 2/20 接受率）。
- 不把对话内容送托管模型（local-first 边界；若 owner 未来明示放开，另走设计变更）。
- 不在本设计内实现——实现按切片另开 batch：S1 确定性提取 + 守卫；S2 会话触发接线；S3 有界摘要 + 接地校验；S4 调和落图 + 旧池子路径移除。
